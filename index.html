1. Public Cloud Deployment Model

FoodBridge runs on Google Cloud Platform (GCP) public cloud infrastructure. Resources are multi-tenant, hosted in secure world-class data centers, and accessible over public Internet endpoints with TLS encryption. It eliminates capital expenditures (CapEx) for physical server hardware, rack cooling, and power redundancy.

2. Service Model: PaaS vs IaaS vs SaaS

PaaS (Platform as a Service): FoodBridge is built completely on PaaS (Backend-as-a-Service). Google provisions, scales, patches, and manages the database and authentication servers.

Contrast with IaaS: If we used IaaS (Virtual Machines like EC2 or GCE), we would manage Linux OS updates, configure Nginx, patch MySQL, setup failover replication, and pay 24/7 even when traffic is zero.

3. Elasticity & Auto-Scaling

During emergency relief food drives, hundreds of donors post simultaneously. Cloud Firestore automatically scales shards horizontally without downtime or manual server provisioning. When traffic subsides at night, resources scale down to zero automatically.

4. Pay-As-You-Go & High Availability

Firebase charges solely for actual reads, writes, and stored bytes, rather than idle compute capacity. Furthermore, Firestore stores data across multiple fault domains in asia-south1 (Mumbai) guaranteeing 99.999% SLA availability and automatic disaster recovery.
